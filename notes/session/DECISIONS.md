# Decisions (append-only)

- **D-1 · 2026-11-11 · Scope = both resume lines; everything is built.** No repo existed. Same account/region as TripMate (free-plan project, Sydney only).
- **D-2 · 2026-11-11 · Everything on AWS is created by OpenTofu in `infra/` and destroyed by `make infra-destroy`.** No console clicking: S3 bucket, Knowledge Base, data source, vector store, Agent, action group, Lambda, IAM roles. The user runs apply/destroy; Claude plans and verifies.
- **D-3 · 2026-11-11 · Models: agent = `amazon.nova-2-lite-v1:0`, embeddings = `amazon.titan-embed-text-v2:0` (1024-d).** Both AVAILABLE/AUTHORIZED in this account with no marketplace form; Claude models are NOT_AVAILABLE here. Model ids are variables so a second model row can be added later.
- **D-4 · 2026-11-11 · Vector store = Amazon S3 Vectors (no idle cost), with OpenSearch Serverless as the documented fallback** if the KB cannot use S3 Vectors in Sydney at apply time. Rationale: OpenSearch Serverless bills ≥ 2 OCUs per hour from creation (≈ $5+/day) — the single biggest cost risk of this project.
- **D-5 · 2026-11-11 · Corpus = a synthetic "company handbook" we write ourselves (~12 Markdown docs: leave policy, expense policy, travel policy, IT/security policy, onboarding, device policy, remote-work policy, holidays, benefits, code of conduct, incident process, glossary).** Rationale: we know the ground truth, so answer quality can be scored deterministically; no licensing issues; interviewers understand it instantly. Fictional company name, no employer content.
- **D-6 · 2026-11-11 · Lambda tools (one action group, OpenAPI schema): `get_leave_balance(employee_id)`, `calculate_reimbursement(category, amount, receipts)`, `get_holiday_calendar(year, region)`, `file_helpdesk_ticket(summary, priority)` (mutating → agent asks for user confirmation before calling).** Data = a small JSON table bundled in the Lambda. The combination "policy from the KB + numbers from a tool" is what the agent must do in several test questions.
- **D-7 · 2026-11-11 · Numbers are measured by `eval/`: a fixed question set (~40 questions, 4 classes: KB-only, tool-only, KB+tool, out-of-scope/refusal) with reference answers and scoring rules.** Metrics: answer correctness (deterministic match on the expected fact/number, no LLM judge), citation present for KB answers, correct tool called with correct arguments (from the agent trace), refusal rate on out-of-scope, latency p50/p95, tokens + estimated cost per question (and real month-to-date cost from Cost Explorer). Report generated (`eval/report.md` + charts + `results.json`), with "what this does NOT prove".
- **D-8 · 2026-11-11 · Two ways to ask: `ka ask "…"` (Typer CLI, boto3 `invoke_agent` with trace enabled, prints citations and tool calls) and a tiny FastAPI + static page for the demo.** Same provider-free pattern as TripMate.
- **D-9 · 2026-11-11 · Retrieval is also testable without the agent:** `ka retrieve "…"` calls the KB `retrieve` API and prints chunks + scores — used for a retrieval-quality metric (does the right doc rank top-3?).
- **D-10 · 2026-11-11 · Cost discipline:** the stack is created, synced, evaluated and destroyed in one session (~1 h). Budget for the whole project < $2. `make cost` prints month-to-date spend from Cost Explorer before and after. Nothing is left running overnight.
- **D-11 · 2026-11-11 · Repo = `~/Desktop/bedrock-knowledge-agent`, GitHub `priyanshu9620/bedrock-knowledge-agent`, notes + memory + `secrets.tar.enc` in the repo (TripMate convention), commit directly to `main`.**
- **D-12 · 2026-11-11 · No local emulation of Bedrock.** Unit tests cover the Lambda handler (pure Python), the eval scorer, the corpus validity and the OpenAPI schema; the integration run is the real AWS stack. CI runs the offline tests only.
- **D-13 · 2026-11-11 · Python 3.11 + uv + boto3, pinned; OpenTofu aws 5.82.2 from the local mirror (same as TripMate).**
- **D-14 · 2026-11-11 · Docs like TripMate:** README (pitch, diagram, measured table), `docs/GUIDE.md`, `docs/RUNBOOK.md` (up/eval/down), `INTERVIEW_PREP/`, `DEMO.md`, `notes/BOOTSTRAP.md`.
- **D-15 · 2026-11-12 · PIVOT: v1 uses Gemini for the model side; Bedrock is parked as v2.** The account is on the AWS Free plan, where every Bedrock model-invocation quota is 0 and not adjustable (P-1); the user chose not to add a card. v1 keeps every AWS piece the Free plan allows (S3 for documents, **Amazon S3 Vectors** for the index, **Lambda** for the tools and for the public API) and replaces only the model calls: `gemini-embedding-001` (768-d) for embeddings and `gemini-3.5-flash-lite` for the agent, both on Google's free tier. Supersedes D-3/D-4's Bedrock-specific parts; D-5…D-14 stand.
- **D-16 · 2026-11-12 · The agent is our own tool-calling loop (Gemini function calling), with the tool definitions generated from the SAME `lambda/openapi.yml`** that a Bedrock action group would consume, and executed by invoking the real Lambda through boto3 with the Bedrock action-group event shape — so `lambda/handler.py` is unchanged and the v2 swap is only the orchestrator. Confirmation before the mutating ticket tool is enforced in code (not by prompt), like TripMate's approval gate.
- **D-17 · 2026-11-12 · Public demo endpoint = a second Lambda with a Function URL** (free tier) running the same agent code, protected by a shared `X-Api-Token`; the Gemini key lives in SSM Parameter Store and is read at cold start. No EC2/ALB this time.
- **D-18 · 2026-11-12 · Bedrock v2 is preserved, not deleted:** the finished Terraform moves to `infra-bedrock-v2/` (validated, planned at 31 resources, never applied) and `docs/V2-BEDROCK.md` tells a future Claude session exactly how to switch when the account is on the Paid plan.
- **D-19 · 2026-11-12 · Resume line v1 is rewritten honestly** around S3 + S3 Vectors + Lambda + Gemini; "Bedrock" is not claimed until v2 is built and measured.
